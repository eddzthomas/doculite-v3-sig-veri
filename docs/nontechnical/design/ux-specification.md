# UX Specification: Plain-Language Version

The application will always explain what is happening. Uploads can be in progress, processing, ready, or failed. Signature checks can be waiting, unsigned, valid and trusted, valid but untrusted, invalid, or unable to check. Signing requests can be drafted, sent, active, completed, declined, expired, cancelled, or failed.

The interface will not rely on color alone. It will show short, plain explanations and let people open detailed evidence when useful. It will clearly say that signing creates a related completed copy rather than changing the original. Error messages will say what happened and offer a safe next step when possible.
